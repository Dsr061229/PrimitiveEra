# 03 · 技术架构与实现方案

## 1. 技术选型

**结论：原生 HTML5 Canvas 2D + Web Audio API + ES Modules，零外部依赖、零素材文件，浏览器直接运行；后期可用 Electron 打包成独立 exe。**

| 候选 | 评估 |
|---|---|
| **原生 Canvas 2D（选定）** | 无依赖、离线可玩、一次性代码落地最可靠；2D 俯视角 + 数百实体的规模，Canvas 2D 性能完全够用；程序化绘图/合成音频均为原生 API |
| Phaser 3 | 引擎能力强，但需要 CDN 或 npm 依赖，离线单机分发麻烦，且本作定制系统多、引擎收益低 |
| Godot | 编辑器工作流优秀，但用户需安装 Godot 才能运行/导出，不符合"写完即玩" |
| Pygame | 画面与音频表现力上限低，粒子/光照实现代价大 |

**运行方式**：ES Modules 受 `file://` 协议限制，提供 `start.bat`（内容：`npx -y http-server -p 8080 -o`，无 Node 时提示）+ 备选方案：构建脚本把所有模块合并为单文件 `PrimitiveEra.html`（双击即玩，最终分发形态）。Electron 打包写入路线图 P2，不阻塞首版。

## 3. 核心循环与实体

- **固定步长**：逻辑 60Hz（`accumulator` 模式），渲染 rAF + 插值，保证数值确定性
- **实体模型**：ECS-lite——一个 `Entity` 基类 + 能力标志位/组件对象（不上完整 ECS 框架，实体种类 ~40 种，直接多态 + 数据驱动足够）
- **性能预算**：同屏实体 ≤ 300（兽潮最大一波 ~60 只）、粒子 ≤ 800（对象池复用）、空间哈希格 128px；掉帧兜底：粒子降档
- **随机数**：带种子的 PRNG（mulberry32），一局一种子——支持"每日挑战"扩展和 bug 复现

## 4. 渲染分层（renderer.js 调度顺序）

1. **地面层**：地形色块 + 噪声纹理细节（离屏 canvas 预烘焙一次，摄像机裁剪绘制）
2. **地物层**：树/石/浆果丛等（按 y 排序参与深度）
3. **实体层**：建筑/人物/野兽统一按 y 排序绘制（伪 2.5D 遮挡）
4. **粒子层**：火星/血珠/木屑/雨雪
5. **光照层**：昼夜色调叠加 + 夜间遮罩挖光洞（见 §5）
6. **UI 层**：世界内 UI（血条/飘字/预警箭头）→ 屏幕 UI（HUD/面板）

**程序化精灵规范**（draw_sprites.js）：每个精灵一个纯函数 `drawWolf(ctx, x, y, state, t)`，用几何图形+描边+关节摆动（sin(t) 驱动四肢/呼吸），全部支持朝向翻转与受击闪白参数。风格统一：2px 深色描边、大色块、低饱和底色+高饱和点缀。

## 5. 光照与昼夜（视觉核心卖点）

- **昼夜色调**：全屏叠一层 `globalCompositeOperation` 色调矩形，颜色按时间插值（正午透明 → 黄昏 rgba 橙红 → 深夜深蓝 0.75 透明度）
- **夜间光洞**：离屏 canvas 涂满暗色 → `destination-out` 画径向渐变圆（篝火/火把/图腾塔）→ 叠回主画布；光圈半径随篝火等级/燃料状态呼吸式波动（sin 微扰，火在"喘息"）
- **光圈是玩法**：光照数据同时供逻辑层查询（敌人减伤判定/恐惧值/村民加成），渲染与逻辑共用一份光源列表

## 6. 音频方案（Web Audio 全合成，零音频文件）

- **SFX 合成配方**（audio.js 内每个音效一个配方函数）：
  - 采集敲击：短噪声脉冲 + 低通滤波，随材质变频率（木闷/石脆）
  - 篝火：循环粉噪声 + 随机幅度包络噼啪脉冲
  - 狼嚎：锯齿波滑音 + 颤音 LFO + 混响（ConvolverNode 用程序生成的脉冲响应）
  - 命中/暴击：方波短音 + 音高下滑；暴击叠高八度
  - 心跳：低频正弦双跳，血量越低越快
  - 立体声像：`StereoPannerNode` 按声源相对玩家方位定位（夜晚听声辨位）
- **程序化 BGM**：五声音阶（宫调式，原始/东方感）序列器
  - 白天：骨笛音色（三角波+颤音）慢速旋律 + 环境鸟鸣随机点缀
  - 夜晚：部落鼓循环（噪声+低频正弦合成鼓），**BPM 与鼓密度挂钩当前威胁**（兽潮波到来时加鼓、Boss 出场换 3/4 拍重鼓）——音乐即警报
  - 主/副音量与静音选项存入设置

## 7. 存档设计（localStorage，两个槽位分离）

- `pe_meta_v1`：局外数据——图腾点、天赋、成就、最高纪录、设置（每次结算写入）
- `pe_run_v1`：局内快照——每个黎明自动存档（只存黎明快照，避免夜战中 S/L 滥用，同时兼容"关机明天继续"）
- 序列化：纯 JSON，实体只存构造参数与状态摘要，载入时重建；版本号字段留迁移空间
- 导出/导入存档字符串（base64）按钮，防浏览器清缓存丢档

## 8. 场景/状态机

```
主菜单 ─→ 职业选择 ─→ 局内(白天⇄黄昏⇄夜晚⇄黎明结算) ─→ 胜利/失败结算 ─→ 天赋树 ─→ 主菜单
                          │                                      
                          └─→ 第15夜黄昏：梦魇之门(独立小场景) ─→ 终局结算
```

局内暂停（Esc）：设置/重开/回主菜单；游戏窗口失焦自动暂停。

## 9. 预留但不实现的接口（架构占位注释即可）

- 多人联机：逻辑 60Hz 固定步长 + 种子随机已是确定性基础，留 `// MP-HOOK` 注释
- 随机地图：`data/map.js` 用声明式布局数据，未来可换生成器
- 手柄：input.js 留抽象动作层（`actions.attack` 而非直查按键）
